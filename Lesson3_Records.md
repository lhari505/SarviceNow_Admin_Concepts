Lecture Summary
---------------

This lecture introduces the fundamental concept of **records** in ServiceNow. A record represents a single entity stored in a database table and is comparable to a row in a spreadsheet. The lecture explains the relationship between **tables**, **fields**, and **records**, and introduces the important concept of the **Sys ID**, a unique identifier assigned to every record in ServiceNow.

* * * * *

Key Points
==========

-   A **record** is a collection of fields representing a single entity.
-   Records are stored inside **database tables**.
-   A **field** is equivalent to a column in a table.
-   A **record** is equivalent to a row in a table.
-   Every record has a unique **Sys ID**.
-   Sys IDs are automatically generated by ServiceNow.
-   Lists and Forms in ServiceNow display records from database tables.
-   Records can represent incidents, users, groups, roles, settings, and much more.

* * * * *

Detailed Notes
==============

1\. Understanding Records
-------------------------

### What is a Record?

A **record** is a collection of related information stored together as a single entity.

Think of a spreadsheet:

| First Name | Last Name | Favorite Fruit | Pet |
| --- | --- | --- | --- |
| John | Doe | Apple | Dog |
| Mark | Miller | Banana | Cat |
| Arthur | Smith | Orange | Fish |

In this example:

-   Each **row** is a **record**.
-   Each **column** is a **field**.

### Simple Definition

A record represents one complete object or entity.

Examples:

-   One user
-   One incident
-   One problem ticket
-   One change request
-   One group

* * * * *

2\. Fields and Records Relationship
-----------------------------------

### Fields

Fields store individual pieces of information.

Examples:

-   First Name
-   Last Name
-   Email
-   State
-   Priority

### Records

A record combines multiple fields to represent one complete item.

Example:

| Field | Value |
| --- | --- |
| First Name | John |
| Last Name | Doe |
| Favorite Fruit | Apple |
| Pet | Dog |

This entire collection is one record.

* * * * *

3\. Retrieving Information from Records
---------------------------------------

To retrieve information, ServiceNow searches records using field values.

### Example

Suppose we need John's favorite fruit.

Search Conditions:

```
First Name = JohnLast Name = Doe
```

Result:

```
Favorite Fruit = Apple
```

This process is how database queries locate specific records.

* * * * *

4\. Database Tables
-------------------

### What is a Table?

A **table** stores related records.

Think of a table as a spreadsheet containing many rows.

### Examples of ServiceNow Tables

| Table | Purpose |
| --- | --- |
| Incident | Stores incident records |
| Problem | Stores problem records |
| Change | Stores change requests |
| User | Stores user records |
| Group | Stores group records |

### Important Concept

A database contains many tables.

Each table contains many records.

```
Database    ↓Tables    ↓Records    ↓Fields
```

* * * * *

5\. Sys ID (System Identifier)
------------------------------

### What is a Sys ID?

Every record in ServiceNow contains a unique identifier called a **Sys ID**.

### Characteristics

-   32-character alphanumeric string
-   Automatically generated
-   Unique across records
-   Used to identify a specific record

### Example

```
62826bf03710200044e0bfc8bcbe5df1
```

This uniquely identifies one record.

* * * * *

6\. Why Sys IDs Are Important
-----------------------------

Sometimes records may contain duplicate information.

Example:

| First Name | Last Name |
| --- | --- |
| Mark | Miller |
| Mark | Miller |

If two users have the same name:

❌ Names cannot reliably identify them.

✅ Sys IDs can uniquely identify each record.

### Key Benefit

The Sys ID acts as a permanent identifier regardless of changes to other fields.

* * * * *

7\. Sys ID Analogy
------------------

### Home Address Example

Think of a Sys ID like a home address.

Every house has:

-   One unique address
-   One exact location

When someone knows your address:

-   They can find your exact house.

Similarly:

When ServiceNow knows a Sys ID:

-   It can find the exact record.

* * * * *

8\. Sys IDs in ServiceNow
-------------------------

Good news for administrators and developers:

You do **not** need to memorize Sys IDs.

### Why?

ServiceNow automatically:

-   Generates them
-   Stores them
-   Retrieves them
-   Displays them when needed

Developers can access Sys IDs using ServiceNow tools and scripts.

-------------------------------

Whenever users interact with ServiceNow:

### List View

Displays multiple records.

Example:

```

```

Each row is a record.

* * * * *

### Form View

Displays one record.

Example:

```

```

Steps / Process
---------------

### How ServiceNow Identifies a Record

#### Step 1

User searches for a record.

#### Step 2

ServiceNow checks field values.

Example:

```
First Name = JohnLast Name = Doe
```

#### Step 3

Matching record is found.

#### Step 4

ServiceNow uses the record's Sys ID internally.

#### Step 5

The exact record is displayed.

Real-World Application
======================

In a ServiceNow implementation:

### Incident Management

Each incident is stored as a record.

Example:

```
INC0010001
```

contains:

-   Caller
-   Assignment Group
-   Priority
-   State
-   Description

* * * * *

### User Management

Each employee is stored as a user record.

Example:

```
John Doe
```

contains:

-   Name
-   Email
-   Department
-   Manager

* * * * *

### Security

Even if two users have identical names, ServiceNow uses their **Sys IDs** to uniquely identify them.

This ensures accurate relationships, permissions, reporting, and integrations.
